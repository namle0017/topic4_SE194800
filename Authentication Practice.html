Mục tiêu bài Lab

Sau bài Lab, sinh viên có thể:

·        hiểu nguyên lý authentication cơ bản và token-based login;

·        xây dựng Login/Register kết nối API;

·        tích hợp Google Sign-In bằng Supabase hoặc Firebase;

·        nhận biết vai trò của Google OAuth, callback, Client ID và session.

Yêu cầu chung: Mỗi câu tập trung vào một mức độ khác nhau, từ mô phỏng authentication → kết nối API thật → đăng nhập bằng Google. Không yêu cầu giao diện phức tạp; ưu tiên flow chạy đúng, code rõ ràng và có thể giải thích được.

Question 1 — Mock Authentication trên DartPad

Mục đích: Hiểu flow authentication cơ bản mà chưa cần backend thật.

Yêu cầu

·        Tạo một file Dart/Flutter có thể chạy trực tiếp trên DartPad.

·        Tạo màn hình Login gồm Email, Password và nút Login.

·        Validate dữ liệu đầu vào cơ bản (không để trống, email hợp lệ, password tối thiểu).

·        Tạo AuthService giả lập backend: kiểm tra một tài khoản demo và trả về mock token nếu đúng.

·        Đăng nhập thành công → chuyển đến Protected Home và hiển thị trạng thái đăng nhập.

·        Đăng nhập sai → hiển thị thông báo lỗi.

·        Có nút Logout để quay lại Login.

Flow gợi ý:  Login UI → Validate → Mock AuthService → Mock Token → Protected Home → Logout

Gợi ý thực hiện

·        Có thể hard-code một tài khoản demo, ví dụ demo@test.com / 123456.

·        Dùng Future.delayed(...) để mô phỏng thời gian gọi API.

·        Mock token chỉ dùng để minh họa nguyên lý; không cần JWT thật.

Kết quả cần đạt: Có thể demo được cả login thành công, login thất bại, protected screen và logout.

Question 2 — Basic Login & Register với API

Mục đích: Chuyển từ mock authentication sang authentication có backend/API thật.

Yêu cầu

·        Xây dựng màn hình Register và Login cơ bản bằng Flutter.

·        Có thể sử dụng API bên ngoài phù hợp cho học tập hoặc tự xây dựng backend/API.

·        Register gửi dữ liệu lên API và xử lý kết quả thành công/thất bại.

·        Login gửi email/username + password lên API.

·        Khi login thành công, lấy access token (nếu API có trả token) và chuyển đến Home.

·        Có loading state và error message khi gọi API.

·        Có Logout để kết thúc phiên đăng nhập.

Flow gợi ý:  Register/Login UI → HTTP Request → Backend/API → Response/Token → Home → Logout

Gợi ý thực hiện

·        Tách phần gọi API ra AuthService/Repository thay vì viết toàn bộ trong UI.

·        Có thể dùng http hoặc dio.

·        Không hard-code password hoặc secret trong source code.

·        Nếu API có token, chỉ cần chứng minh app nhận được token và dùng nó làm trạng thái authenticated; không bắt buộc làm refresh token.

Kết quả cần đạt: Register/Login hoạt động với API thật và sinh viên giải thích được request → response → token → navigation.

Question 3 — Login via Google

Mục đích: Tích hợp xác thực bên thứ ba bằng Google OAuth. Có thể chọn Supabase hoặc Firebase.

Yêu cầu

·        Thêm nút “Continue with Google” / “Sign in with Google”.

·        User chọn tài khoản Google và hoàn thành OAuth flow.

·        Sau khi đăng nhập thành công, hiển thị ít nhất tên/email hoặc trạng thái authenticated.

·        Có Logout và đăng nhập lại được.

·        Giải thích ngắn được vai trò của Google OAuth và Supabase/Firebase trong flow.

Hướng A — Google + Supabase (gợi ý)

1.        Google Auth Platform: Tạo/chọn Google Cloud Project, cấu hình ứng dụng OAuth.

2.        Audience: Chọn đối tượng sử dụng; nếu đang Testing thì thêm Test Users.

3.        OAuth Clients: Tạo Web Client; nếu chạy Android thì tạo Android Client với đúng package name và SHA fingerprint.

4.        Callback: Thêm callback URL do Supabase cung cấp vào Google OAuth configuration.

5.        Supabase: Enable Google Provider và cấu hình Google Client ID/Client Secret phù hợp.

6.        Flutter: Khởi tạo Supabase bằng Project URL + Publishable/Anon Key và gọi Google OAuth.

7.        Return to app: Cấu hình redirect/deep link nếu chạy mobile; nhận Supabase session sau khi Google xác thực.

Flow gợi ý:  Flutter → Supabase → Google OAuth → Supabase Callback → Session → Flutter/Home

Hướng B — Google + Firebase

·        Tạo Firebase Project và thêm ứng dụng Android/Web tương ứng.

·        Enable Google Sign-In trong Firebase Authentication.

·        Cấu hình package name, SHA fingerprint và file cấu hình theo platform.

·        Dùng firebase_auth + google_sign_in (hoặc cách tương đương theo platform) để thực hiện đăng nhập.

·        Nhận Firebase user/session và điều hướng vào Home.

Thuật ngữ cần biết

Google OAuth: Cơ chế cho phép ứng dụng xác thực user bằng tài khoản Google mà không cần ứng dụng biết password Google.

Client ID: Mã định danh ứng dụng đối với Google OAuth.

Callback / Redirect URL: Địa chỉ Google/Supabase quay về sau khi xác thực hoàn tất.

SHA fingerprint: Fingerprint của certificate/keystore dùng để ký Android app; không phải SHA của điện thoại/emulator.

Supabase/Firebase: Dịch vụ Authentication giúp quản lý OAuth, user/session và tích hợp với Flutter.

Lưu ý: Không đưa Client Secret, service-role key hoặc password vào source frontend. Khi chạy Android, package name và signing SHA phải khớp cấu hình OAuth.

TÀI LIỆU HƯỚNG DẪN TÍCH HỢP API VÀ BẢO MẬT XÁC THỰC

Tài liệu này hướng dẫn chi tiết về cấu hình, kiến trúc bảo mật và cách triển khai các luồng xác thực (Email/Mật khẩu, Google OAuth qua Supabase, OTP xác thực Email, Lưu trữ Token) trong dự án football_management_fe.

1. TỔNG QUAN KIẾN TRÚC & NGUYÊN TẮC BẢO MẬT

1.1. Nguyên Tắc Cốt Lõi (Golden Rules)

  1. Không gọi nhà cung cấp nhạy cảm từ Client:
  • Mobile App (Flutter) tuyệt đối không chứa API Key / Secret Key của các nhà cung cấp bên thứ ba (như dịch vụ gửi SMS/Mail, Mailgun, SMTP).
  • Toàn bộ việc sinh OTP, gửi mail xác thực và kiểm tra token đều được Backend API (BFF) trung gian đảm nhận.
  1. Luồng Google OAuth chuẩn qua Supabase:
  • Flutter App khởi tạo luồng OAuth qua supabase_flutter và mở trình duyệt ngoài.
  • Sau khi người dùng đăng nhập tài khoản Google thành công trên trình duyệt, hệ thống điều hướng về app qua Deep Link: footballmanagement://login-callback.
  • App nhận session từ Supabase và gửi session.accessToken (Supabase JWT) lên Backend API qua endpoint: POST /api/auth/google.
  • Backend xác thực token này với Supabase rồi cấp phát JWT application_access_token nội bộ của hệ thống.
  • Tuyệt đối không dùng token của Supabase để gọi trực tiếp các API nghiệp vụ của Backend.
  1. Lưu trữ Token an toàn:
  • Sử dụng flutter_secure_storage (thông qua SecureStorageService) để mã hóa và lưu trữ token an toàn trên Android Keystore và iOS Keychain.
  • Không lưu token trong SharedPreferences dạng plain-text thông thường.
  1. Quy trình kích hoạt tài khoản bằng OTP:
  • OTP trong hệ thống dùng để xác thực kích hoạt email sau khi đăng ký tài khoản (không phải 2FA lúc login).
  • Đăng ký thành công trả về 202 Accepted kèm verificationId.
  • Người dùng nhập OTP 6 chữ số để kích hoạt tài khoản trước khi có thể đăng nhập.

3.3. Quản Lý Token An Toàn (SecureStorageService)

File: lib/core/storage/secure_storage_service.dart

import 'package:flutter_secure_storage/flutter_secure_storage.dart';

class SecureStorageService {

  SecureStorageService._({FlutterSecureStorage? storage})

    : _storage = storage ?? const FlutterSecureStorage();

  static final SecureStorageService instance = SecureStorageService._();

  static const String _accessTokenKey = 'application_access_token';

  final FlutterSecureStorage _storage;

  Future<void> saveAccessToken(String token) async {

    await _storage.write(key: _accessTokenKey, value: token);

  }

  Future<String?> getAccessToken() async {

    return _storage.read(key: _accessTokenKey);

  }

  Future<void> clearAccessToken() async {

    await _storage.delete(key: _accessTokenKey);

  }

}

3.5. Tầng Dịch Vụ API Xác Thực (AuthApiService)

File: lib/features/auth/data/services/auth_api_service.dart

import 'package:dio/dio.dart';

import '../../../../core/constants/api_endpoints.dart';

import '../../../../core/network/api_exception.dart';

import '../../../../core/network/api_result.dart';

import '../models/login_request.dart';

import '../models/login_response.dart';

import '../models/register_request.dart';

import '../models/registration_response.dart';

import '../models/resend_email_request.dart';

import '../models/verify_email_request.dart';

class AuthApiService {

  const AuthApiService(this._dio);

  final Dio _dio;

  Future<ApiResult<LoginResponse>> login(LoginRequest request) async {

    final data = await _postRequest(ApiEndpoints.login, request.toJson());

    final result = data['result'] as Map<String, dynamic>?;

    return _toResult(data, LoginResponse.fromJson(result!));

  }

  Future<ApiResult<LoginResponse>> loginWithGoogle(String supabaseAccessToken) async {

    final data = await _postRequest(ApiEndpoints.googleLogin, {

      'accessToken': supabaseAccessToken,

    });

    final result = data['result'] as Map<String, dynamic>?;

    return _toResult(data, LoginResponse.fromJson(result!));

  }

  Future<ApiResult<RegistrationResponse>> register(RegisterRequest request) async {

    final data = await _postRequest(ApiEndpoints.register, request.toJson());

    final result = data['result'] as Map<String, dynamic>?;

    return _toResult(data, RegistrationResponse.fromJson(result!));

  }

  Future<ApiResult<void>> verifyEmail(VerifyEmailRequest request) async {

    final data = await _postRequest(ApiEndpoints.verifyEmail, request.toJson());

    return _toResult(data, null);

  }

  Future<ApiResult<RegistrationResponse>> resendEmailVerification(ResendEmailRequest request) async {

    final data = await _postRequest(ApiEndpoints.resendEmail, request.toJson());

    final result = data['result'] as Map<String, dynamic>?;

    return _toResult(data, RegistrationResponse.fromJson(result!));

  }

  Future<Map<String, dynamic>> _postRequest(String path, Map<String, dynamic> body) async {

    try {

      final response = await _dio.post<Map<String, dynamic>>(path, data: body);

      final data = response.data;

      if (data == null) throw const ApiException('Server did not return data.');

      if (data['success'] != true) throw ApiException(_extractErrorMessage(data));

      return data;

    } on DioException catch (error) {

      final data = error.response?.data;

      if (data is Map<String, dynamic>) {

        throw ApiException(_extractErrorMessage(data));

      }

      throw ApiException(error.message ?? 'Could not connect to server.');

    }

  }

  ApiResult<T> _toResult<T>(Map<String, dynamic> json, T data) {

    return ApiResult<T>(

      code: json['code'] as int? ?? 0,

      message: (json['message'] as String?)?.trim().isNotEmpty == true

          ? (json['message'] as String).trim()

          : 'Request completed successfully.',

      data: data,

    );

  }

  String _extractErrorMessage(Map<String, dynamic> json) {

    final message = (json['message'] as String?)?.trim();

    final result = json['result'];

    final details = result is List

        ? result.map((item) => item.toString()).where((item) => item.isNotEmpty)

        : const Iterable<String>.empty();

    final parts = [

      if (message != null && message.isNotEmpty) message,

      ...details,

    ];

    return parts.isEmpty ? 'Request failed.' : parts.join('\n');

  }

}

3.6. Tầng Repository Lưu Trữ Token (AuthRepository)

File: lib/features/auth/data/repositories/auth_repository.dart

import '../../../../core/storage/secure_storage_service.dart';

import '../../../../core/network/api_result.dart';

import '../models/login_request.dart';

import '../models/login_response.dart';

import '../models/register_request.dart';

import '../models/resend_email_request.dart';

class AuthRepository {

  const AuthRepository({

    required this.apiService,

    required this.storageService,

  });

  final AuthApiService apiService;

  final SecureStorageService storageService;

  Future<ApiResult<LoginResponse>> login(LoginRequest request) async {

    final response = await apiService.login(request);

    await storageService.saveAccessToken(response.data.accessToken);

    return response;

  }

  Future<ApiResult<LoginResponse>> loginWithGoogle(String supabaseAccessToken) async {

    final response = await apiService.loginWithGoogle(supabaseAccessToken);

    await storageService.saveAccessToken(response.data.accessToken);

    return response;

  }

  Future<ApiResult<RegistrationResponse>> register(RegisterRequest request) =>

      apiService.register(request);

  Future<ApiResult<void>> verifyEmail(VerifyEmailRequest request) =>

      apiService.verifyEmail(request);

  Future<ApiResult<RegistrationResponse>> resendEmailVerification(ResendEmailRequest request) =>

      apiService.resendEmailVerification(request);

}

3.7. Điều Phối Google OAuth & Nút Bấm

File: lib/features/auth/presentation/widgets/google_auth_coordinator.dart

import 'package:flutter/material.dart';

import '../../../../core/widgets/app_message.dart';

import '../../../home/presentation/pages/home_page.dart';

import '../../data/repositories/auth_repository.dart';

class GoogleAuthCoordinator {

  const GoogleAuthCoordinator._();

  static bool _isProcessing = false;

  static Future<void> processSession({

    required BuildContext context,

    required String supabaseAccessToken,

    required AuthRepository authRepository,

    required void Function(bool isLoading) setLoading,

  }) async {

    if (_isProcessing) return;

    _isProcessing = true;

    setLoading(true);

    try {

      final response = await authRepository.loginWithGoogle(supabaseAccessToken);

      if (!context.mounted) return;

      AppMessage.success(context, response.message);

      Navigator.pushAndRemoveUntil(

        context,

        MaterialPageRoute(builder: (context) => const HomePage()),

        (route) => false,

      );

    } catch (error) {

      if (!context.mounted) return;

      AppMessage.error(context, error.toString());

    } finally {

      _isProcessing = false;

      if (context.mounted) {

        setLoading(false);

      }

    }

  }

}

3.8. Màn Hình Đăng Nhập (LoginPage)

File: lib/features/auth/presentation/pages/login_page.dart

Tích hợp lắng nghe Supabase OAuth và gọi đăng nhập email/mật khẩu:

@Override

void initState() {

  super.initState();

  _authRepository = AuthRepository(

    apiService: AuthApiService(DioClient.instance),

    storageService: SecureStorageService.instance,

  );

  _listenToSupabaseAuth();

}

void _listenToSupabaseAuth() {

  if (!AppConfig.isSupabaseConfigured) return;

  _authStateSubscription = Supabase.instance.client.auth.onAuthStateChange

      .listen((data) {

        final event = data.event;

        final session = data.session;

        if (event == AuthChangeEvent.signedIn && session != null) {

          GoogleAuthCoordinator.processSession(

            context: context,

            supabaseAccessToken: session.accessToken,

            authRepository: _authRepository,

            setLoading: (loading) => setState(() => _isGoogleSubmitting = loading),

          );

        }

      });

}

Future<void> _signInWithGoogle() async {

  if (!AppConfig.isSupabaseConfigured) {

    AppMessage.error(context, 'Supabase chưa được cấu hình. Vui lòng kiểm tra file .env.');

    return;

  }

  setState(() => _isGoogleSubmitting = true);

  try {

    await Supabase.instance.client.auth.signInWithOAuth(

      OAuthProvider.google,

      redirectTo: AppConfig.supabaseRedirectUrl,

      authScreenLaunchMode: LaunchMode.externalApplication,

      queryParams: const {'prompt': 'select_account'},

    );

  } catch (error) {

    if (mounted) {

      setState(() => _isGoogleSubmitting = false);

      AppMessage.error(context, 'Không thể mở đăng nhập Google: $error');

    }

  }

}
